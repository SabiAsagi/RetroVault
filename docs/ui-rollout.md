# 겜자취 UI 적용 현황

기준: 게임 위키·아카이브의 정보 탐색을 우선하고, 내 다락의 수집 재미와 친근한 표현을 더한다. 디자인 원본은 https://www.figma.com/design/lwGQeaTSYGSU4vNuIj2lW6 이다.

## 1차 기본 UI

- 겜자취 로고, 내 다락 명칭, 공통 색상·테마 선택기
- 홈: 검색, 게임·플랫폼·제작사·연대기 탐색, 실제 게임 데이터
- 게임 탐색: 기존 필터·정렬·목록/카드·페이지 이동 유지
- 게임 문서: 목차, 개요·시대 정보·설치 사양·리뷰·기본 정보·수정 제안
- Figma의 가상 게임 및 출처 예시는 실제 데이터로 취급하지 않는다.
- 실제 표지 이미지는 유지하고 표지가 없을 때만 카트리지 형태를 사용한다.
- 출처별 근거와 문서 수정 이력은 DB 기능이 아직 없으므로 검증된 기록처럼 표시하지 않는다.

## 플랫폼·제작사 UI

- Figma: 플랫폼/제작사 목록·상세의 PC·모바일, 화이트·블랙·레트로 24개 프레임. 목록 기준: node `91:47`, `91:309`.
- 공통 검색·분류·필터·정렬·카드/목록 전환·페이지 직접 이동, 로딩/실패/검색 결과 없음 안내.
- 실제 기기 이미지와 회사 로고를 사용하고 이미지 실패 시 이름과 기호로 대체한다.
- 상세 문서는 소개·기본 정보·관련 게임으로 구분한다. 긴 사양·대표작은 줄바꿈하고, 없는 정보는 확인 중으로 표시한다.
- 관련 게임 카드의 문서 이동과 유통사 전체 게임 필터 연결을 정리했다. DB 스키마와 기존 데이터를 변경하지 않는다.

## 모델·에디션과 기기 소장 기록 (2026-10-21)

- 플랫폼·제작사 도감 명칭, 모바일 도감 통합 탭 및 두 도감 전환 링크.
- 게임·플랫폼·제작사 페이지 이동 시 상단 이동. 플랫폼 문서는 같은 시리즈의 기기 링크와 모델·에디션/주변기기 탭으로 구분.
- PS4/PS5, DS Lite 모델·일본 색상과 주변기기 등 공식 출처를 확인한 19개 기초 기록. 자료 확인일·지역·구성·호환성·공식 출처를 상세에 표시. 전체 모델을 수록한 것으로 표현하지 않는다.
- 제품 사진은 public/hardware/, 구조화된 기초 자료는 src/data/hardware-catalog.json에서 관리한다. 새 자료 추가 시 공식 근거·지역·이미지 출처와 권리 관계를 확인한다.
- HardwareCollectionItem 테이블을 Neon 기존 main DB에 추가했다. 기존 게임 컬렉션과 분리하며 본인만 접근한다. 보유/위시·수량·메모, 수정과 제거 지원.
- SQL은 prisma/migrations/20261021000000_hardware_collection/migration.sql에 보관한다. 이 SQL만 Neon 콘솔에서 트랜잭션으로 적용했다. 기존 DB의 Prisma migration baseline은 별도이므로 전체 db push/reset 또는 migrate deploy를 무조건 실행하지 않는다.
- 타입 검사 및 테스트 23개 통과. 로그인 계정의 빈 기기 기록과 저장 입력 화면, 모바일 분류/사진/하단 다섯 탭을 확인했다. 실제 DB의 INSERT/UPDATE를 트랜잭션으로 확인 후 ROLLBACK했고, 잔여 테스트 기록 0개를 확인했다. 브라우저 저장 버튼을 통한 실제 계정의 영구 QA 기록은 추가하지 않았다.
- Figma 기존 플랫폼 상세 6개 프레임에 시리즈·모델/주변기기·비공개 소장 동선을 확장. 기준 PC 91:147, 모바일 91:259.

## 연대기 UI (2026-10-22)

- Figma PC·모바일 × 화이트·블랙·레트로 6개 편집 가능 프레임. 기준 PC 101:430, 모바일 101:559.
- 시대·연도 선택 후 한 해를 세로로 읽는 구성, 검색·종류 필터·표시 밀도·기기 더 보기 및 로딩/오류/빈 기록 안내.
- 연도 주소 공유와 기존 홈 연도 링크 호환, 문서 이동 후 뒤로 가기에서 연도 복원. 긴 게임명 줄바꿈과 모바일 5열 연도 선택.
- 공개·승인 자료만 조회하며 관리자 사건 조회와 공개 사건 조회를 분리. 삭제·성인·미출시 게임과 잘못된 1970년 날짜를 제외. 게임은 DB에서 연도별 최대 20개를 조회하며 일부 기록임을 안내.
- 이 단계는 DB 스키마와 기존 기록을 변경하지 않는다. 타입 검사 및 전체 테스트 30개 통과.
- 이번 작업 범위는 연대기까지이며, 내 다락·다락 구경·관리자 개별 UI는 다음 단계다.

## 다음 UI 적용 순서 — 사용자 확정 (2026-10-21)

각 단계는 현재 기능 점검 → Figma PC·모바일 및 상태별 시안 → 코드 적용 → 검증 순서로 진행한다. 블랙·화이트·레트로 테마를 포함한다.

1. 연대기: 완료. 연도 탐색, 정보 밀도, 필터 및 모바일 사용성.
2. 내 다락: 게임·기기 기록의 진열/목록, 필터·그룹·정렬·공개 범위, 담기·수정 창.
3. 다락 구경: 공개 컬렉션과 프로필, 개인 기록 구분, 탐색·친구·공유 흐름.
4. 관리자 탭: 역할별 접근, 검토·자료 보강·오류·완료 상태. 기기 자료 관리 흐름 포함.

공통 테마가 적용되어도 나머지 화면의 개별 UI 재설계가 완료된 것은 아니다. 정책은 legal-launch.md의 검토 사항이 남아 있다.

## 운영 도메인

retrovault.kro.kr은 Vercel retro-vault 프로젝트의 Production에 연결된다. 검증된 기능 배포를 운영 환경으로 빌드/승격한다. Git main 병합과는 별개이며, 이후 미리보기 변경은 검증 후 운영 승격한다. DNS를 미리보기 주소로 돌리지 않는다.
